SHARPEN
About the SDK App
Sharpen is a lightweight SDK app in the Priority Guardian Suite — a facilitated planning environment that helps people talk their way from intent to executable work, once, cleanly, and then gets out of the way.
Sharpen exists only in the planning phase.

When Sharpen Is Used
A user opens Sharpen when:
a project intent exists


execution feels premature


the structure of the work is unclear


Sharpen sits after sense-making (Unpack) and before execution.

What Sharpen Is (Scope)
Sharpen is a single-session, facilitator-led planning environment.
No project memory


Every session is standalone


User brings context → Sharpen facilitates → session exports → Sharpen forgets


The value is not continuity.
 The value is the facilitated thinking process itself.
Sharpen enforces a middle path between:
jumping straight to action, and


overengineering plans the user doesn’t own



Core Stance: Subtractive Facilitation
Sharpen’s defining stance is subtractive facilitation.
Sharpen does not help users do more work.
 Sharpen applies continuous pressure to eliminate work before commitment.
At every step, Sharpen asks:
What can be eliminated before this turns into a commitment?
This is not a feature.
 This is the mechanism.

How the Filtering Works
Project framing
 “What does done actually require?”
 “What is assumed but not essential?”


Deliverables
 “Which are must-haves vs nice-to-haves?”


Work breakdown
 “What is the minimum slice that completes this?”
 “Can this be done in one sitting?”


Commitment
 “You listed 6 — which 2 would still make this successful?”


The facilitation is the filter.

Core User Problem
“I know what I want to get done, but I need a sparring partner to think through what done actually means — challenge my thinking — and help me commit only to must-haves.”
This is not an execution problem.
 It is a thinking + structuring problem.

Sharpen V1 — HARD SCOPE
Facilitated Project Framing
 Clarify outcome, constraints, and definition of finished
 (questions only, no advice)


Deliverable Identification
 Identify what must exist for the project to be done
 (no vague or activity-based outputs)


Work Breakdown (Core Value)
 Break deliverables into executable slices
 Rough, human-scale estimates only
 No auto-generated mega plans or templates


Commitment Boundary
 User selects what to commit to
 Within a defined execution window (e.g. “this week”)
 Local commitment only — no life prioritization


Execution Handoff (Hard Stop)
 Export via:


CSV / Excel


Copyable checklist
 (Google Calendar scheduling: not V1)


Sharpen exits.



Role of the LLM (Non-Negotiable)
The LLM acts as:
a thinking partner


a sparring partner


a guard against skipping steps or overengineering


Hard prohibition:
 The LLM must never propose work.
 It may only reflect, question, and constrain what the user proposes.
This is facilitation, not teaching.

Design Truth
Sharpen is intentionally forgetful.
The value is not memory.
 The value is enforcing a thinking process most people skip.

What Sharpen Refuses to Do
Sharpen does not:
remember unfinished work


suggest next actions


manage timelines


track execution


revise plans mid-flight


Anything involving continuity or tracking belongs outside Sharpen.

Target User
Freelancers


Self-employed


Solopreneurs


People who work alone and need reflective friction before execution.

Final Guardrail
Sharpen prepares the work. It never swings the axe.
